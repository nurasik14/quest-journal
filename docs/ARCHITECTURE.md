# Daily Quest Journal: plan

## Context
Nurasyl wants a personal daily quest system. Each day it gives 3 AI-generated quests, plus a weekly boss quest. Finishing quests earns coins, which are spent in a reward shop (a treat, a café meal, a manga). Each day also records notes and a satisfaction rating. The AI should know Nurasyl's personality through a knowledge base that grows over time, like Hermes's memory files. It must be free beyond the existing Claude Max plan.

**Decision:** this is a new, separate app, not part of `~/Projects/Learning-Blog`. That blog is a static Hugo site on *public* GitHub Pages, so it can't save data and would expose private ratings and notes. Selected days could still be published to the blog later through a `publish: true` flag.

## Decisions
- Stack: **TypeScript, using Bun + Hono (API) + Svelte (Vite SPA, PWA)**
- Access: the app runs on the PC where `claude` is logged in. The phone reaches it over **Tailscale** as an installable PWA.
- Data: plain Markdown and YAML in a **separate private git repo**, committed automatically after each save
- Quests: **3 daily + 1 weekly boss**. They're generated by Claude through headless `claude -p`, which uses the Max subscription, so there are no API costs.
- Rewards: **coins + shop**

## Layout
```
~/Projects/quest-journal/          # app code (its own repo)
  server/  index.ts (Hono), store.ts (md/yaml I/O), ai.ts (claude -p), economy.ts, git.ts
  web/     Svelte SPA: Today, Evening, Shop, History/Stats, Profile/Insights, Onboarding
  .env     DATA_DIR=~/quest-data

~/quest-data/                      # private data repo
  kb/profile.md       # written by you, seeded by the onboarding interview
  kb/insights.md      # maintained by the AI, every change approved by you
  days/2026-10-25.md  # frontmatter: date, energy, satisfaction, mood, quests[], coins, streak; body: Highlight/Notes/Gratitude
  weeks/2026-W43.md   # the boss quest + weekly review
  rewards.yaml        # shop items with coin prices and cooldowns
  quests.yaml         # fallback pool for when Claude isn't available
  ledger.md           # coin earn/spend log (or derived from the day files)
```
Libraries: `gray-matter` + `yaml` for frontmatter, `zod` to validate the AI's JSON, `simple-git` or `Bun.spawn git`.

## AI engine (`server/ai.ts`)
- `Bun.spawn(["claude","-p",prompt,"--output-format","json","--model","sonnet"])`: the reply is parsed and validated with zod. It retries once, then falls back to the `quests.yaml` pool.
- **Generate day** (when the morning check-in is submitted): the context is profile, insights, the last 14 days (a compact summary), recent quest titles (so nothing repeats), weekday, energy 1–5 and coin balance. It returns 3 quests in different categories and difficulties: `{title, why, category, difficulty, coins}`.
- **Weekly boss** (the first open of each ISO week): one bigger quest for the week with a big coin payout.
- **Reroll:** 1 per day. It regenerates a single quest and passes the rejected one in as a negative signal.
- **Reflect** (after the evening save): Claude proposes add/edit/remove changes to `insights.md`, each citing dates as evidence. The UI shows them as a diff and you accept or reject each one.
- **Onboarding:** a quiz of about 15 questions (Big-Five-style plus hobbies, budget, city, limits, goals). Claude drafts `profile.md` from the answers and you edit it.

## Economy (`server/economy.ts`)
- Difficulty sets the coins: easy 10, medium 20, hard 35, boss 100. Each 7-day streak gives a bonus.
- Shop: you buy an item, which deducts coins and logs the purchase. Starting rewards: treat 30, café meal 80, manga 150 (all editable in `rewards.yaml`).

## Pages
Today (energy check-in, 3 quests + boss, done/fail/reroll, 👍/👎 per quest) · Evening (rating 1–10, mood tags, highlight, notes, gratitude, then insight suggestions) · Shop (balance, items, wishlist) · History (calendar heatmap of satisfaction, average satisfaction per category, streak, "this day last month") · Profile (edit profile.md and insights.md)

## Build order
1. Scaffold the Bun + Hono + Svelte app, with the data repo init and the day-file read/write. Use a hardcoded quest pool at first.
2. Today + Evening pages, and git auto-commit
3. `ai.ts`: generation, reroll, weekly boss, fallback
4. Onboarding + reflect/insights approval flow
5. Coins, shop, streaks
6. History/stats, PWA manifest + service worker, bind to the Tailscale IP

## Verification
- `bun test` for the frontmatter round-trip, coin math, streaks and the fallback when `claude` fails (stub the spawn)
- Manual: run `bun dev`, do onboarding, then run a morning check-in and confirm 3 valid quests appear and `days/<today>.md` parses (`git log` in `~/quest-data` shows the commit). Complete a quest and check the coin balance, buy an item, do the evening save and approve an insight, then confirm `kb/insights.md` changed.
- Phone: open `http://<tailscale-ip>:PORT`, install the PWA and complete a quest.
- Seed 30 fake days and check the heatmap and the category stats.
