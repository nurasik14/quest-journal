## Bugs (ranked)

### MED-1: Replacing a hand-edited `profile.md` from onboarding loses the hand edit from git history
- **Repro:**
  1. Start the quiz on `/onboarding`.
  2. Hand-edit `DATA_DIR/kb/profile.md` (append `HAND EDIT mid-quiz`).
  3. Finish the quiz and press Save → 412 notice "…save again to replace it".
  4. Press Save again → 200.
  5. Run `git -C DATA_DIR log -p --all -- kb/profile.md | grep -c "HAND EDIT"`.
- **Expected:** as on the evening path (M2 BUG-1, `today.ts:366-377`), the on-disk hand-edited version is committed (`… hand_edit`) when the 412 happens, so the user can recover it after choosing "replace".
- **Actual:** `0`. The only commit is `qj: profile` (template → new text). The hand-edited text is gone for good. The same applies to `PUT /api/kb/insights` from any client.
- **Suspected file:** `server/src/kb.ts` `putKb`, or `store.writeKb`'s stale path. Mirror the `lastWrittenEtag` + `git.touch(... "hand_edit") + flush` snapshot from `today.ts`.

### LOW-1: The `INSIGHT_BLOCKLIST` profile exception is a substring match
- **Repro:** `blockedTerms("Feels fat after café days", "I have fatigue")` → `[]`. `blockedTerms("diet days", "my sister is a dietitian")` → `[]`.
- **Expected:** the term is only excused when the user wrote *that word* (P-AC10 "a term the user wrote"). Both should be blocked.
- **Actual:** blocked body/diet terms slip through whenever the profile contains a longer word that includes them.
- **Suspected file:** `server/src/reflect-rules.ts` `blockedTerms` (`prof.includes(term)`). Use a `\b…\b` test.

### LOW-2: `GET /api/insights/proposals/:id` doesn't validate the id (traversal inside DATA_DIR)
- **Repro:** `curl localhost:4399/api/insights/proposals/..%2F..%2Fquests`.
- **Actual:** 422 `invalid_file`, `kb/proposals/../../quests.yaml has values…`. It reads any `*.yaml` in the data repo, and YAML parse-error messages can echo snippets of that file. `store.abs` does stop escapes **outside** DATA_DIR (`Path escapes DATA_DIR`).
- **Expected:** 404, as `decide` already returns (it calls `isValidDate`).
- **Suspected file:** `server/src/kb.ts` `getProposal` / `readProposal`. Add `isValidDate(id)` at the top.

### LOW-3: In dark mode the disabled "Apply my choices" looks enabled
- **Repro:** set `data-theme=dark` → Evening with a ready proposal and nothing chosen.
- **Actual:** the button is `disabled` but rendered as a solid dark fill with 9:1 light text, the same as an active button (`M4-14`). In light mode it is visibly muted (`M4-10`).
- **Suspected file:** the `qj-btn` disabled style in the theme's dark tokens, or `ProposalList.svelte`.

### LOW-4: Decide rewrites the proposal YAML, so hand comments are dropped
- **Repro:** append `# my hand comment` to `kb/proposals/<date>.yaml` → decide (after the 412 reload).
- **Actual:** the comment is gone.
- **Expected:** comment-preserving edits, like `store.updateYaml` (M2 BUG-2), per the "survive hand edits" convention. Low, because proposal files are mostly app-owned.
- **Suspected file:** `server/src/kb.ts` `decide` (`stringifyYaml(cur.file)`).

### LOW-5: The sanitiser keeps invisible/bidi characters, and a soft hyphen evades the suspicious flag
- `sanitizeOpText("a‮b")` keeps U+202E (RTL override). `"zero​width"` keeps U+200B. `SUSPICIOUS_OP.test("ig­nore previous")` → false.
- Rendering is plain text, so this is spoofing only, not XSS.
- **Suspected file:** `server/src/insights.ts` `CONTROL_RE`. Add `­​-‏‪-‮⁠-⁤﻿`.

### Nits
- **NIT-1:** `maxInsightId` scans every line, including `%% comments %%`, so a comment mentioning `i-0042` made the next id `i-0043` (`kb.ts`). Harmless, since ids are never reused.
- **NIT-2:**
  - What happened: the model's text "Drawing hands shows up on most calm evenings" was accepted with a user edit on 10-27, then re-proposed verbatim for 10-26.
  - Why it wasn't caught: the duplicate check only compares against current insight texts (similarity < 0.8 to the user's edited wording).
  - Suggested fix: `validateReflect` could also compare against the `proposed_text` of accepted ops (`reflect-rules.ts`).
- **NIT-3:** every Evening visit to a date without a proposal logs a console 404 for `GET /api/insights/proposals/<date>`. It's expected but noisy; a list query or 204 would avoid it.
- **NIT-4:** sprint AC3 says the care case returns `reflect: {care: true}`, but the implementation returns `reflect_skip: "care"`. The UI handles it correctly; only the doc and contract drift.
