## Bugs (ranked)

### BUG-1 (Medium): `logicalDate` is wrong for an hour on DST-transition days
- **Where:** `server/src/clock.ts:96`, `logicalDate()` subtracts `rolloverHour × 3600000` ms of elapsed time and then takes the local date. On a DST day, "4 elapsed hours ago" isn't "wall clock before 04:00".
- **Repro:** `logicalDate(new Date("2026-10-25T02:30:00Z"), "Europe/Berlin", 4)` (local 03:30 CET, after fall-back).
- **Expected:** `2026-10-24` (before 04:00 local). **Actual:** `2026-10-25`. Also 03:59 CET → `2026-10-25`. Spring-forward: `2026-03-29T02:30:00Z` = 04:30 CEST → expected `2026-03-29`, actual `2026-03-28`. New York 2026-11-01 03:30 EST → `2026-11-01` (expected `10-31`).
- **Impact:** For one hour twice a year in DST zones, quests or streaks can land on the wrong day. No impact for Asia/Almaty or Asia/Hong_Kong (no DST).
- **Suggested fix:** take the wall-clock parts in `tz` (`wallParts`). If `hour < rolloverHour`, use the local calendar date minus 1 day, otherwise the local date. Add the Berlin and NY cases above to `clock.test.ts`.

### BUG-2 (Low): a save that changes nothing still rewrites a hand-edited file, which strips the user's YAML comments
- **Where:** `server/src/store.ts` `updateMd()`. `mergeChanges` correctly returns `raw` untouched, but the file is always re-serialized (`serializeMarkdown`), and `out !== text` holds whenever the original had comments or non-canonical formatting.
- **Repro:** write `days/2026-10-06.md` with `# my comment` in the frontmatter and `satisfaction: 6   # good day`, then call `store.updateDay("2026-10-06", d => { d.satisfaction = 6 })`.
- **Expected:** no write (`changed:false`), since the value is identical and every section is present. **Actual:** `changed:true`, and both comments are gone (`---\ndate: 2026-10-06\nsatisfaction: 6\n---…`).
- **Why it matters:** M2's evening form re-sends every field on each save, so an unchanged re-save will rewrite Obsidian-edited files. Comment loss on a *real* change is a documented known gap. Losing them on a no-op isn't necessary.
- **Suggested fix:** if `deepEqual(view, after)`, no owned section changed and no normalization was needed, return early without writing. Alternatively, use the `yaml` Document API for comment-preserving edits (already a COULD in the backlog).

### BUG-3 (Low): CRLF files end up with mixed line endings after a save
- **Where:** `server/src/markdown.ts` `applySections` / `serializeMarkdown`.
- **Repro:** day file with `\r\n` endings and a `## Notes` section. Call `updateDay(d => { d.notes = "crlf2" })`.
- **Actual:** `"---\ndate: …\n---\n## Highlight\n\n## Notes\r\ncrlf2\n\n## Gratitude\n"`. The frontmatter becomes LF, the untouched heading keeps `\r\n`, and the new content is LF. **Expected:** consistent endings (either keep CRLF or normalize the whole file). The file still reads back fine, so this is cosmetic, but Windows/Obsidian sync may show noisy diffs.

### BUG-4 (Low / nit): `process.env` is read outside `config.ts`
- **Where:** `server/src/git.ts:89`, `env: { ...process.env, GIT_TERMINAL_PROMPT: "0", ...env }`.
- AC2 says config.ts is the only module that reads `process.env`. This is a harmless pass-through to the child process (needed for `HOME`/`PATH`), but it breaks the stated rule. Either pass the env in via `GitOptions` from `index.ts`, or note the exception in the AC.
