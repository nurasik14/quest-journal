## New findings (ranked)

### R-BUG-1 (Medium, regression from the BUG-2 fix): app-created day files store all quests on one ~850-char flow-style line
- **Repro:** fresh `DATA_DIR`, `GET /api/today`, `POST /api/today/checkin {"energy":2}`, then `cat days/<date>.md`.
- **Expected:** block-style quests, like the spec example in `docs/brainstorm/architecture.md` §day file (`quests:` followed by `  - id: …` / `    slot: 1` …). CLAUDE.md: "Markdown day files must stay readable and editable by hand." The first M2 run produced block style.
- **Actual:**
  ```
  quests: [{id: 2026-10-27-1, title: "Take 5 photos on one theme (green things, lanterns or signs)", why: "A theme turns a walk into a hunt. …", category: …, …}, {id: 2026-10-27-2, …}, {id: 2026-10-27-3, …}]
  ```
  `awk` max line length is **845**. This reproduced on 3 fresh data dirs (energies 2, 3 and 4). It affects every day the app will ever create, and `rejected:` in M3 will follow the same path.
- **Suspected file:** `server/src/markdown.ts:175` in `editYamlText`: `if (YAML.isCollection(prev) && YAML.isCollection(node) && prev.flow) node.flow = true;`. The template's `quests: []` (`store.ts:355` defaults) is an *empty* flow sequence, so the 3 generated quests inherit flow style. Suggested fix: only inherit `flow` when `prev.items.length > 0`, or never for `quests`/`rejected`/`checkpoints`. Add a regression test asserting that check-in on a new file yields `quests:\n  - id:` block style.

### R-BUG-2 (Low): any 412 records a `day <date> hand_edit` reason even when nothing was hand-edited
- **Repro:** `PUT /api/days/<today>/evening` with `If-Match: deadbeef` (or `*` on an existing file) while another app write is pending.
- **Expected:** the snapshot commit only gets a `hand_edit` reason when the on-disk file actually differs from the last commit. Otherwise the reason shouldn't be added.
- **Actual:** commit `ea4423e qj: boss 2026-W44 checkpoint, day 2026-10-26 hand_edit` contains only `weeks/2026-W44.md`, but its message claims a day hand edit. Each such 412 also blocks the response for up to 5 s (`STALE_SNAPSHOT_MS`) to flush.
- **Suspected file:** `server/src/today.ts:403-408`. Gate on `git status --porcelain <file>` / a dirty check, or let `commitNow` drop reasons whose files aren't in the staged set.

### R-BUG-3 (Low): the stale panel lists fields that didn't change on disk as "changed elsewhere"
- **Repro:** load Evening with notes "Line one…", hand-edit only the Highlight on disk, change Notes in the app, and seal.
- **Expected (builder's claim, PROGRESS "stale panel lists only real conflicts"):** no Notes entry, because disk Notes == the loaded Notes. The panel should mention the Highlight that did change, or say that untouched fields were updated from disk.
- **Actual:** the panel shows "Notes on disk: Line one / ## Gratitude / sneaky", which is the user's own previous text, and says nothing about the Highlight that was silently replaced in the field (`img/M2r1-02-evening-412-rebased-390.png`). No data is lost: the untouched field correctly adopted the disk value.
- **Suspected file:** `web/src/lib/eveningForm.ts` `rebaseForm`: `conflicts` uses `!same(form[k], theirs[k])`. A real conflict needs `!same(theirs[k], loaded[k])` as well.

### Observations (not bugs)
- The init commit can merge with the week's creation as `qj: init, boss 2026-W44 pool (+hand edits)`. This happens because `init` touches with no file list, so its files count as "hand edits" (`git.ts:165`). It's timing-dependent (the UI-walk instance had separate `qj: init` / `qj: boss … pool`). It's cosmetic.
- A 412 on a *quarantined* day file commits the broken file as `hand_edit` (`e5d346a`). That's arguably right, since the user's bytes are preserved in history, but it's worth knowing.
- `   ## indented` (≤3 leading spaces) and a bare `##` line aren't escaped. The app's parser doesn't treat them as headings, so the app round-trips them exactly, but Obsidian renders them as headings. This is cosmetic only.
- Satisfaction edits normalize whitespace before an inline comment (`6   # felt ok` → `8 # felt ok`). The comment itself is kept.
- PROGRESS's builder smoke test noted that `QJ_FAKE_NOW` is ignored with `NODE_ENV=production`. That's confirmed by design (`config.ts:186`), so I ran with `SERVE_WEB=true` and no `NODE_ENV`.
