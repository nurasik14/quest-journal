## Bugs (by severity)

### MED-1: the `BottomSheet` focus trap leaks on day sheets that show a rating (goal 15)
- **Repro** (390×844, any seeded garden):
  1. Open `/archive` and press Enter on the "Sun 25 Oct" plot. Focus is on the h2.
  2. Press Tab: "Write in the ledger". Then Tab, Tab, Tab… The next Tab moves to "Close" and **stays on "Close"** forever. It doesn't wrap.
  3. Press Shift+Tab from "Write in the ledger". **Focus leaves the dialog** to "Read that page" in the month-ago card behind it.

  The same leak happens on the 22/24/26 Oct sheets. The broken-page sheet (no rating) traps correctly.
- **Expected:** Tab and Shift+Tab cycle among the dialog's focusable controls (`aria-modal="true"` promises this).
- **Actual:** forward Tab is stuck, and backward Tab escapes into the page behind the modal.
- **Cause** (`web/src/lib/components/BottomSheet.svelte` ~l.41): the node list is `'a[href], button:not([disabled]), textarea, input, [tabindex]:not([tabindex="-1"])'`. It includes the 10 radio `<input>`s of the read-only `HerbRating`, which are disabled through `<fieldset disabled>`. Their own `.disabled` is false, but they aren't focusable.
  - So `first` is radio 1. `first.focus()` is a no-op, so Tab from "Close" goes nowhere.
  - And `activeElement === first` is never true, so Shift+Tab isn't intercepted.
- **Suggested fix:** filter to what can really take focus. For example, keep nodes where `!n.matches(':disabled') && n.tabIndex >= 0 && n.getClientRects().length > 0` (`:disabled` matches fieldset-disabled descendants). Add a unit/DOM test with a disabled fieldset inside the sheet.

### LOW-1: the About "Image sources" toggle is a 26 px-tall tap target
- **Repro:** `/profile` at 390 → About → the `<summary>` "Image sources" measures **316 × 26 px**.
- **Expected:** ≥ 44 px (DESIGN-BRIEF tap targets).
- **Suspected file:** `web/src/routes/Profile.svelte` (summary styling). Add `min-height: 44px` / padding.

### NITs
- **NIT-1:** the read-only `HerbRating` (sheet and month-ago card) exposes all 10 option labels ("1 of 10: One of the worst days…" … "10 of 10…") as disabled radios. Screen readers will announce a 10-item disabled radio group for a value that's also printed as "8/10 Very good…". This is the same root as MED-1. A read-only variant could render `role="img"` with one label. `web/src/lib/theme/HerbRating.svelte` (designer-owned).
- **NIT-2:** with `claude` missing, startup still prints `[server] AI: claude --model sonnet…`, and `/api/health` says `enabled:true` alongside `bin:null, reason:"claude_missing"`. That's correct, but mixed signals for a reader of the journal log. `server/src/index.ts`.
- **NIT-3:** the README demo hard-codes `--today 2026-10-26`. A future run seeds days far in the past, so the default 4-week garden looks empty. Dropping `--today` (it defaults to the logical today) would fix it. `README.md` §"Try it with demo data".
- **NIT-4:** garden plots are 43.6 px at 390 and 33.6 px at 320. The brief says ≥ 44, `screens.md` says min 40, and goal 14 explicitly accepts 320. Noted, not a goal failure.
- **NIT-5:** the empty garden (< 3 days) shows only sticker + copy. `screens.md` §Garden states also mentions "a grid of dashed plots", while goal 17 (committed) asks only for sticker + seeds copy. That's for the designer to decide.
- **NIT-6:** an unlisted `Host` gets 421 on `/api/*`, but the static shell (`/`) still answers 200. That's harmless (the shell holds no data), but it differs from the "421 until listed" wording if read broadly. `server/src/app.ts` host middleware.
- **NIT-7:** `After=/Wants=network-online.target` in a **user** unit has no effect, since the user manager doesn't see the system target. It's harmless (verify passes) but could mislead. `deploy/quest-journal.service`.
- **Observation:** the `/api/stats` p95 is 124 ms over HTTP with 400 full days on this laptop, against the builder's 53 ms in-process. It's within budget, but the margin is about 25 ms if days grow heavier. Not a bug.
